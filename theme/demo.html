Migration plan

Move page delivery to the edge control plane

Replace the single-origin release path with independently deployable control and content services while preserving public links and the existing CLI contract.

Owner
Platform systems

Plan thesis

Separate the control and content paths first, prove parity against mirrored traffic, then move production reads before writes.

Target state

The migration removes a shared deployment boundary. Authentication remains on the control origin; public HTML and the house theme remain on the content origin.

Before

One release path

API writes, public reads, and theme delivery move together and share rollback timing.

Changes to
After

Two bounded services

Control and content deploy independently against one durable page record.

Phase 02 — mirror production reads

Outcome: every public page response is compared for status, headers, and normalized body output before the new service receives user traffic.

  • Replay a bounded sample of current page IDs against both services.
  • Record mismatches without logging page bodies or credentials.
  • Hold cutover until seven consecutive days pass without a contract mismatch.

Required hand-offs

  1. D1
    Schema parityRequired before mirrored reads can be trusted.
  2. DNS
    Origin routesPrepared after parity, activated during cutover.
  3. OBS
    Mismatch telemetryRequired for the release decision and rollback watch.

Cutover decision

Move reads before writes. This keeps the rollback boundary narrow while the new public path proves itself under production traffic.

Not selected

Single cutover

Fastest transition, but couples public rendering and authenticated writes in one rollback event.

Recommended

Reads, then writes

Proves the highest-volume path first and leaves the current control service available during observation.

Implementation impact

The work stays inside service boundaries and deployment configuration. The stored page contract and client commands do not change.

  • workers/src/content.tsModifyServe themed and raw pages from the shared record.
  • workers/src/control.tsModifyKeep scoped API behavior aligned with the current server.
  • workers/wrangler.tomlConfigureBind both services to the production database and distinct routes.
  • cmd/waymarkNo changeExisting commands and response shapes remain the compatibility boundary.
