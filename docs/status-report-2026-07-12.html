What shipped

Branch opencode/cloudflare-workers-d1 delivered a TypeScript port of the Go server to two Cloudflare Workers sharing one D1 database: a control worker (API and admin) and a content worker (public pages). The two workers have separate entry points, so the origin separation is enforced structurally, with 421 Host gating in both directions.

  • Full rename from Columbia Pages to Waymark: the CLI is now waymark, environment variables use the WAYMARK_* prefix, and config lives at ~/.config/waymark.
  • Hourly cron replaces the Go expiry-sweep goroutine.
  • Rate limiting is now persisted in D1.
  • Theme stays single-source: deploy scripts re-embed theme/theme.css, so the house theme continues to live in one file.
  • Docs: docs/self-hosting/cloudflare-workers.md plus a new docs/self-hosting/ENV.md with the complete env and secret reference.

Verification

  • go test passes across all four packages; go vet is clean.
  • The workers' vitest suite passes 64/64, running real SQL against the actual migration via node:sqlite.
  • tsc typecheck is clean for both the source and test configs.
  • An earlier live end-to-end run with wrangler dev and the real CLI exercised device login, themed and raw publishing, CRUD, TTL expiry, 421 Host gating, and 401 paths — full parity with the Go server.

Security review

A high-scrutiny review covered the full diff. The following were verified clean: origin separation; unguessable page IDs (rejection-sampled base62, about 71 bits of entropy, crypto RNG, uniformity-tested); fully parameterized SQL; token and secret hashing with constant-time comparisons; __Host- cookies with CSRF and Origin checks; the admin passcode absent from the content worker bundle; and byte-for-byte themed/raw output parity with the Go server.

Five issues were found and fixed before merge (commit 195b92d):

Issues found and fixed in commit 195b92d
IssueFix
Silent JSON type coercion in the pages API ttl_days: "7" made a page never expire and raw: "false" flipped themed to raw. Wrong-typed fields now return strict 400s, matching the Go behavior.
Missing response headers on control-worker JSON Responses (including the token-bearing device poll) lacked Cache-Control: no-store and security headers. Every response is now stamped.
Uncaught errors on malformed percent-encoding Bad encoding in paths or cookies threw uncaught and returned 500. Now handled as 404 or logged-out.
Non-atomic device-grant claim Grant claim and token insert now run as one D1 batch transaction, so a failed insert cannot burn a grant.
No body-size caps on unauthenticated endpoints Request bodies on unauthenticated endpoints are now capped.

Codex branch

The parallel codex/cloudflare-workers-d1 branch was assessed and is strictly superseded: it is a single 755-line worker whose origin split is only runtime-gated (the admin code ships inside the content bundle), it has no cron sweep, and its tests are thin.

One idea is worth an optional future cherry-pick: a schema-level trigger enforcing one token per grant. That would be defense-in-depth only — the current fix is already race-safe and tested.

ℹ
Recommendation

Delete the codex/cloudflare-workers-d1 branch.

Onboarding a new device or agent

Production is live, so onboarding is now the only recurring step. On the new machine or agent, run waymark login --server https://waymark-control.leoeccentric.workers.dev, then approve the device once in the browser. The issued device token lasts 90 days.

Custom domains can be attached to both workers later without any data loss.

Your questions, answered

Any uncommitted work?
No. The tree is clean and everything is merged and pushed.
Daily logins?
No. wrangler login happens once ever; the admin passcode is only needed when approving a new device; device tokens last 90 days.
Will links work everywhere?
Yes. Published links are plain public HTTPS served from the Cloudflare edge — they work from any network, device, or cloud agent, and your Mac can be asleep, unlike the current Tailscale-Funnel setup.
